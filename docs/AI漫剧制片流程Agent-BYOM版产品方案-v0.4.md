# AI 漫剧制片流程 Agent：BYOM 版产品方案（v0.4）
> 上游：v0.1（市场分析）/ v0.2（工具竞品与调度方案）/ v0.3（对话式 Agent 方案）
> **本版核心变更（用户拍板）**：① 支持用户配置自己的模型（BYOM）② Agent 只做业务流程控制 ③ 以大多数用户的需求为设计基准
> 变更影响：砍掉"代采算力"模式 → 商业模式变为纯软件订阅；架构从云 SaaS 调整为**桌面应用优先**（用户 Key 不经过我们的服务器）。

## 一、需求挖掘：大多数用户到底卡在哪
### 1.1 用户金字塔（基于 2026-11 调研数据反推）
```
        ▲ 层3 小工作室/承制团队（约 172 家认证厂商+数千小团队）
       ▲▲   痛点：多项目并行、团队协作、交付管理
      ▲▲▲   已被神经猫(市占60%+)/万兴剧厂重兵服务 → 不是我们的主战场
     ▲▲▲▲
    ▲▲▲▲▲  层2 尝试过工具的个人创作者 ← 【大多数用户，核心付费层】
   ▲▲▲▲▲▲   画像：已注册即梦/可灵账号（免费额度用过），做过几条短片，
  ▲▲▲▲▲▲▲   但从没独立做出一部完整连贯的剧
 ▲▲▲▲▲▲▲▲   规模：内容创作群里"想做漫剧"的沉默大多数（估算十万级）
```

### 1.2 层2 用户（大多数）的五句原话式痛点
| # | 痛点（调研佐证） | 对应需求 |
|---|------------------|----------|
| P1 | "没有一个工具能包打天下，我即梦出图、可灵生成、剪映拼接，素材全散在文件夹里"（尧图横评原文） | **流程串联**：把已有工具账号串成一条线 |
| P2 | "角色一致性靠运气，做连续剧第一集和第五集不是同一张脸"（数商云/横评共性痛点） | **资产锁定**：角色库+参考图复用 |
| P3 | "不会写分镜，不知道一个镜头该描述到什么程度"（社群高频提问） | **模板库**：分镜/提示词模板，填空式创作 |
| P4 | "免费额度撑不住，一条片子 100-150 次生成起步，废片全是白花钱"（电影界横评） | **成片率**：标记可用/废弃，知道哪个环节在漏钱 |
| P5 | "即梦画质好但贵，海螺便宜跑量，可我不知道怎么搭着用"（横评"省三成成本"分工法） | **路由建议**：按镜头类型推荐用自己的哪个模型 |
**关键洞察**：层 2 用户不缺模型（各家账号都有），**缺的是"制片流程的 know-how"**——先做什么后做什么、每步检查什么、失败了怎么补救。这正是"Agent 提供业务流程控制"的需求依据。
### 1.3 需求优先级（Kano 初判）
| 需求 | Kano 分类 | 说明 |
|------|-----------|------|
| 流程串联（P1） | **必备型** | 没有它产品不成立 |
| 资产锁定（P2） | **期望型** | 决定留存的核心投入 |
| 模板库（P3） | **期望型** | 决定小白上手速度 |
| 成片率统计（P4） | 期望型 | 给用户"变专业"的掌控感 |
| 路由建议（P5） | **兴奋型** | 超预期惊喜，口碑传播点 |
| 团队协作（层3 需求） | 本期不做 | 神经猫的主场，V3 再看 |
## 二、产品定位（修订版）
**一句话**：模型你自带，流程我来管——一个懂漫剧制片 SOP 的桌面 Agent，把你手里的即梦/可灵/海螺/任意模型账号，串成一条从剧本到成片的生产线。
| 项 | 定义 |
|----|------|
| 产品形态 | **桌面应用（Tauri + 本地引擎）优先**，V2 再评估 Web 协作版 |
| 我们提供 | 制片流程引擎（状态机+检查点）、模型适配层、资产库、模板库、成片率统计 |
| 我们不提供 | 算力（用户自己的 Key）、模型（BYOM）、内容承诺（辅助创作工具定位） |
| 核心信任点 | **你的 API Key、素材、成片，全程只存在你自己的电脑**——零数据合规负担，信任逻辑与财务工具"数据不出电脑"同构 |
### 为什么桌面版是对的（架构决策依据）
1. BYOM 最干净实现：Key 存本地，调用从用户电脑直达模型厂商，**我们的服务器零接触**——单人开发者不用建算力中转、不用管数据安全合规
2. 匹配你的技术栈（Tauri + FastAPI 本地引擎）
3. 素材是视频大文件，本地处理比云端上传便宜且快
4. 买断/订阅均可，无服务器运维成本 → 业余可维护
5. 对手全是云 SaaS，桌面版天然差异化（内网/隐私敏感用户同样受益）
## 三、BYOM 模型配置层设计（核心新模块）
### 3.1 四类能力适配器
流程中每个环节声明需要的能力，用户在"模型设置"里把自己的模型绑到能力上：
| 能力槽 | 默认流程绑定 | 兼容用户配置示例 |
|--------|--------------|------------------|
| 文本（剧本/分镜生成） | 任意 OpenAI 兼容 API | DeepSeek / Qwen / GLM / 本地 Ollama |
| 生图（定妆/关键帧） | 即梦 API / OpenAI 兼容绘图 | 即梦 / SD（本地 ComfyUI）/ 任意 |
| 生视频 | 可灵 / 海螺 API | 可灵 / 海螺 / Vidu / 即梦 |
| TTS | MiniMax / 任意 TTS API | MiniMax / 火山 / 本地 edge-tts |
### 3.2 配置体验（不会用的人也能配）
| 编号 | 功能 | 规则 | 验收标准（GWT） |
|------|------|------|-----------------|
| FR-01 | **模型连接向导** | 选厂商 → 粘贴 Key → 自动发一条测试请求 → 显示该模型支持的能力槽与单价（如可获取） | Given 用户粘贴可灵 Key，When 测试，Then 10 秒内返回"视频能力可用 ✓，余额/单价已读取" |
| FR-02 | **能力自动推荐** | 按已连接模型自动生成推荐绑定（关键镜头→画质强的，过场→便宜的），用户可一键改 | Given 用户连了即梦+海螺，When 新建项目，Then 生成推荐路由表并解释理由 |
| FR-03 | **能力缺口提示** | 流程启动前检查能力槽是否齐；缺生视频槽时给出该槽位的厂商注册引导链接（不强制） | Given 只配了生图，When 启动生产，Then 明确提示"缺少视频模型"并附引导，不静默失败 |
| FR-04 | 本地模型支持 | Ollama/ComfyUI 地址填入即视为模型（文本/生图槽），照顾隐私敏感与零成本用户 | — |
| FR-05 | Key 安全 | Key 加密存本地，日志与导出的调试信息自动脱敏 | 导出的任何文件不含完整 Key |
### 3.3 与流程层的解耦
```
┌─────────────── Agent 对话层（v0.3 方案，不变）───────────────┐
│  剧本 → CP-1 → 定妆 → CP-2 → 路由 → 批量生成 → CP-3 → 成片  │
├───────────────────────────────────────────────────────────────┤
│  流程引擎（状态机/检查点/断点续作/资产库/成片率统计）★产品核心★ │
├───────────────────────────────────────────────────────────────┤
│  模型适配层：四类能力槽 × OpenAI 兼容 + 各厂 SDK + 本地模型     │
├───────────────────────────────────────────────────────────────┤
│  用户模型：即梦/可灵/海螺/DeepSeek/Ollama/ComfyUI/…（BYOM）    │
└───────────────────────────────────────────────────────────────┘
```
**流程引擎与模型完全解耦**：新增一个厂商适配器不影响流程；流程模板升级不碰模型层。这也是单人长期维护的关键——模型层变化快（适配器工作量小），流程层沉淀深（是护城河）。
## 四、MVP 范围（收窄再收窄）
| 模块 | V1 包含 | 砍到后续 |
|------|---------|----------|
| 流程 | 单一"3 集短剧"模板 + 三检查点（CP-1/2/3） | 多题材流程库、自定义流程 |
| 模型 | OpenAI 兼容文本 + 海螺 + 可灵三个适配器（你有 MiniMax 资源可先跑通海螺） | 即梦/Vidu/本地模型 |
| 资产 | 角色库（锁定+全剧注入） | 场景库、服装库 |
| 模板 | 逆袭题材 1 套分镜提示词模板 | 模板市场 |
| 统计 | 成片率（按模型/镜头类型） | 成本账本（BYOM 下用户自己在厂商侧付费，账本降级为估算参考） |
| 界面 | 桌面单机 | Web 协作、团队 |
**V1 验收标准**：用户自带可灵+海螺 Key，用桌面 Agent 对话完成一部 3 集漫剧，中途三检查点各停一次，角色 5 集内不换脸，全程不需要看说明书。
## 五、定价（纯软件，无算力差价）
| 版本 | 定价 | 内容 | 逻辑 |
|------|------|------|------|
| 免费版 | ¥0 | 1 个项目 + 全流程 + 水印导出 | 让用户用自己 Key 先跑通一集，验证价值 |
| 专业版 | **¥69/月 或 ¥499/年** | 无限项目、无水印、资产库、成片率报表 | 对比锚点：模型月费本身 30-50 元/家，工具费 < 一家模型月费 |
| 买断版 | ¥699（可选试水） | 桌面版终身 + 1 年流程模板更新 | 与你财务工具买断逻辑一致，测试桌面用户偏好 |
> BYOM 的定价心理优势：用户感觉"钱都花在模型上（值），工具只是顺手买的"，比绑算力加价模式信任度高。
## 六、风险更新
| 编号 | 风险 | 等级 | 应对 |
|------|------|------|------|
| RK-01 | 厂商 API 变动导致适配器失效 | 高 | 适配器接口最小化（只依赖生成+查询两个动作）；适配器做成可热更新配置 |
| RK-02 | 用户 Key 配置门槛劝退小白 | 高 | FR-01 向导 10 秒出结果；预置"跟着教程 5 分钟配好"视频；层1 用户靠免费版慢慢转化 |
| RK-03 | 与 v0.2 判断冲突：不做成本账本/代采后，差异化是否还成立？ | 中 | 成立且更聚焦——差异化从"算账"变为"**流程 know-how + 模型中立 + 桌面隐私**"；账本降级为成片率统计 |
| RK-04 | 大厂出官方编排（即梦一键漫剧升级） | 中 | 大厂只编排自家模型；我们的价值恰是**跨厂商中立**，这是大厂结构性做不到的 |
| RK-05 | 模板/流程被抄袭 | 中 | 模板可抄，检查点状态机+资产锁定+成片率数据沉淀抄不走；持续迭代题材模板库 |
## 七、30 天执行计划（更新版）
1. **W1-2**：模型适配层骨架 + 海螺适配器跑通（用你的 MiniMax 资源零成本验证）
2. **W2-3**：流程状态机 + CP-1/2/3 检查点（Tauri 桌面壳 + 本地 FastAPI）
3. **W3-4**：逆袭题材一套模板 + 桌面对话 UI 原型；找 3-5 个社群用户用自己的 Key 内测
4. **W4 复盘**：内测用户能否独立跑通一集？→ 决定 V1 正式立项
