## 二、决策影响分析：为什么必须 C 端先行
**业余 + 无机构资源的双重约束推导**：
```
业余做 → 每周可投入约 10-15 小时（估算）→ 无法承接 B 端私有化部署的驻场/响应义务
没有种子机构 → 企业版共创没有第一批用户 → B 端冷启动成本极高
        ↓
两条约束指向同一个结论：
  先做 C 端工具箱（个人版/代账版）
  → 业余可维护（用户自助，无驻场义务）
  → 赚现金流 + 积累代账用户池
  → 从付费的代账会计中筛选"小机构老板"作为未来共创机构
  → 企业版在 C 端月收入接近工资线时启动
```
**战略主线一句话**：用 C 端 299/899 的买断现金流养技术资产和用户池，等代账版付费用户里出现 3-5 个主动要"团队版"的机构老板，企业版才立项——需求是被验证出来的，不是赌出来的。
## 三、三阶段执行路线图（业余节奏）
### 阶段一：C 端个人版验证期（第 1-6 个月）
**目标**：验证"本地+隐私+五件套"有人付费；目标 100-300 单（保守按 100 单规划）。
| 周期 | 里程碑 | 业余节奏下的具体动作 |
|------|--------|----------------------|
| 第 1-2 月 | 技术验证 | 本地 OCR 基准测试（无独显电脑跑 PaddleOCR 50 张发票）；工资条引擎 MVP（复用最高频场景先跑通）；软著申请提交（周期 2-4 个月，越早越好） |
| 第 3 月 | 产品可用 | 个人版五大工具中先上 2 个（工资条+发票识别）；官网落地页 + 假门测试（¥299 预约按钮，投 500 元验证） |
| 第 4-6 月 | 上市与迭代 | 代码签名购买 + 杀软白名单申报；短视频账号开更（每周 2 条，复用现有内容自动化工作流）；上线销售，月目标 15-50 单 |
**业余开发取舍原则**：只做"下载即用、用户自助"的功能，砍掉一切需要客服手把手的功能（如自定义模板引擎放二期，先用 3 套内置模板）。
### 阶段二：代账版与用户池积累期（第 6-12 个月）
**目标**：代账版上线，付费用户中沉淀 50+ 代账会计；月收入 ¥5,000-15,000（估算）。
| 里程碑 | 说明 |
|--------|------|
| 代账版（¥899）上线 | 多账套切换 + 批量增强（200 张/批）；从个人版"导入多套 Excel"行为中识别代账用户并定向推销 |
| 社群渗透 | 加入 20-30 个代账/会计社群（v0.2 渠道策略）；免费版月度额度作为社群见面礼 |
| **共创机构筛选器** | 代账版用户中主动咨询"团队能不能一起用""能不能多人访问"的用户 = 天然共创线索，建立"企业版候名单"，记录其机构规模/痛点原话 |
| 关键判定指标 | 候名单 ≥3 家机构老板且痛点一致 → 进入阶段三；<3 家 → 说明机构需求未验证，继续深耕 C 端 |
### 阶段三：企业版立项期（第 12-18 个月，条件触发）
**启动条件（全部满足才立项）**：
1. C 端月收入 ≥ ¥8,000（约等于一线城市最低生存线的一半，验证产品能养活自己）
2. 企业版候名单 ≥3 家机构老板，且能说清"愿意为团队版付多少钱"
3. 你每周可投入时间 ≥20 小时（或 C 端收入允许减薪转半职）
立项后按 v0.3 需求方案执行：种子版免费 6 个月换共创 + 案例授权，FR-01~08 功能清单不变。
