# 企业级应用：赛道评估与需求方案（v0.3）
> 上游文档：v0.1（产品评估）、v0.2（痛点/买点/定价/销售）
> 本文回答：**个人/小团队做企业级（B 端）应用，有哪些赛道可做？推荐哪条？需求方案是什么？**
> 数据来源：2026-11-18 公开调研（费控 SaaS 市场数据、财政部电子凭证新政、代账行业规模），估算处已标注。

## 一、企业级赛道评估矩阵
评估维度：市场空间（能不能长大）/ 竞争烈度（还有没有位置）/ 小团队切入点（不需要 50 人销售团队能不能做）/ 技术栈匹配度（你现有能力的复用度）。
| # | 赛道 | 市场空间 | 竞争烈度 | 小团队切入 | 技术栈匹配 | 综合判断 |
|---|------|----------|----------|------------|------------|----------|
| T1 | **费控/报销 SaaS** | 85 亿元，增速 30%+ | ★★★★★ 红海：每刻（已双转正）、合思、分贝通、有成、用友、泛微全部在场 | 差：正面进入需销售团队+资金 | 高 | ❌ 不做正面 |
| T2 | **智能票据处理引擎（API/OEM 供给）** | 电子发票系统大盘 850 亿元，数电票占 92% | ★★★ 头部做全套方案，"引擎层供给"有空位 | 好：卖给软件商/集成商，1 个渠道客户=批量终端 | **极高**（本地工具箱 OCR 直接复用） | ✅ 重点候选 |
| T3 | **代账机构 AI 工作台（B2B2C）** | 代账机构 13.68 万家，服务 5500 万+中小微，70% 企业外包财税 | ★★★ 财税 AI 热但代账 SaaS（如柠檬云等）功能老旧 | 好：代账机构决策链短、社群集中（v0.2 已验证触达路径） | 高（票据+工资条+报表全是代账刚需） | ✅ **推荐主赛道** |
| T4 | 电子会计档案（四性检测） | 政策刚需（财政部令 79 号 + 电子凭证标准） | ★★ 厂商少但需资质与 OA/ERP 集成能力 | 中：需绑定 T1/T2 玩家做配套 | 中 | 备选（T3 的增值模块） |
| T5 | 财务 BI / 经营数据可视化 | 通用 BI 已内卷（帆软/观远） | ★★★★ | 差 | 高（pyecharts+duckdb） | ❌ 作为 T3 的报表模块而非独立产品 |
| T6 | 企业监控告警/可观测平台 | 可观测赛道热但大厂（阿里/华为/开源）通吃 | ★★★★ | 差：需长期驻场运维服务 | 极高（银河项目直接复用） | ❌ 商业化路径不适合单人 |
| T7 | 信创适配/私有化部署服务 | 政策红利持续 | ★★★ | 中：项目制、靠人脉 | 高（K8s 熟练） | 备选现金流业务 |
### 结论
**主赛道 = T3（代账机构 AI 工作台）+ T2（票据引擎作为底座）**，理由：
1. **市场底盘真实且付费方明确**：13.68 万家代账机构，AI 落地后"一人 270 户 → 800 户"的人效差（行业调研数据）就是采购理由，ROI 可量化。
2. **与 C 端工具箱共享 80% 技术资产**：发票 OCR、验重、工资条、台账引擎全部复用，等于把 v0.2 的个人版（¥299）向上延伸出机构版（万元级）——同一条技术曲线卖两次。
3. **避开了 T1 红海的正面战场**：费控 SaaS 头部打的是"企业直客"，代账机构是被头部忽视的"服务者人群"（他们不是买费控，是买"产能"）。
4. **政策窗口期**：财政部财会〔2024〕11 号、12 号要求会计软件适配电子凭证数据标准 + 金税四期穿透监管 → 代账机构**必须升级工具**，这是"不得不买"的合规驱动。

## 二、产品需求方案：代账机构智能工作台
### 2.1 定位与一句话
**产品名（暂定）**：账台 / 代账工厂
**一句话定位**：给代账机构的私有化智能产能平台——一人管 50 户的会计，装上后能管 150 户；客户数据留在机构自己服务器上。
| 项 | 内容 |
|----|------|
| 目标客户 | 代账机构（3-50 人规模，一人 30-80 户）、财务外包团队 |
| 核心价值 | ①人效提升（票据自动入账+自动申报准备）②多户切换/批量操作 ③客户数据私有化（机构的信任资产）④合规留痕（应对金税四期） |
| 不做 | 不做企业直客费控（避开 T1）、不做全盘 ERP、第一年不做自动申报（政策敏感，先做申报准备） |
| 部署形态 | 私有化（Docker/K8s 一键部署，复用你的 K8s 能力）+ 机构局域网内多终端访问 |
### 2.2 角色与核心场景
| 角色 | 场景 | 高频操作 |
|------|------|----------|
| 机构负责人（老板） | 看产能与人效、客户续费 | 仪表盘：每人/每户工时、票据积压量、客户风险清单 |
| 主办会计 | 月度建账、票据审核、申报准备 | 批量取票→自动分类→异常标记→人工复核→生成凭证草稿 |
| 外勤/助理 | 收票、贴票、扫描 | 手机拍照上传/微信文件导入→自动去歪斜纠偏→进待处理池 |
| 客户（企业） | 交票、看进度（轻门户） | 微信 H5 上传票据、查看"我的账处理到哪一步" |
### 2.3 功能架构（FR 摘要，V1 范围）
```
┌─────────────── 机构门户（Web，局域网/VPN 访问）───────────────┐
│  ①客户账套管理    ②智能票据池    ③凭证生产线    ④报表中心     │
│  ⑤员工工作台      ⑥老板驾驶舱    ⑦客户轻门户(H5)              │
├──────────────────────────────────────────────────────────────┤
│  引擎层：票据 OCR（复用本地工具箱）│ 验重/验真 │ 自动分类       │
│         凭证生成规则引擎（复用银河规则引擎，科目映射规则可配置）  │
│         工资条引擎（复用）│ 台账/报表引擎（duckdb+pyecharts）   │
├──────────────────────────────────────────────────────────────┤
│  部署层：Docker Compose 单机版 / K8s 多节点版 │ 本地对象存储(MinIO) │
└──────────────────────────────────────────────────────────────┘
```
**V1 功能清单（每条可验收）**：
| 编号 | 功能 | 关键规则 | 验收标准（GWT） |
|------|------|----------|-----------------|
| FR-01 | 多客户账套 | 账套隔离（库级/模式级）；一键切换；批量操作跨账套 | Given 机构有 80 户，When 批量导入 80 户票据，Then 各户数据严格隔离、互不可见 |
| FR-02 | 票据智能池 | 全渠道采集（扫描/拍照/微信文件/邮箱）；OCR 字段化；自动按客户+月份+票种归类 | Given 单日 300 张混合票据，When 进入池，Then 自动归类准确率 ≥90%（人工只处理标记项） |
| FR-03 | 验重验真 | 同票号跨账套/跨月份查重；台账黑白名单 | Given 已入账发票再次出现，When 入池，Then 标红"疑似重复"并定位首次入账记录 |
| FR-04 | 凭证草稿生成 | 科目映射规则可配置（客户自定义模板）；生成草稿而非直接入账，会计确认 | Given 100 张已审票据，When 触发生成，Then 产出 100 张凭证草稿，科目映射命中 ≥85%，未命中项标记待人工 |
| FR-05 | 老板驾驶舱 | 人效（在管户数/处理票据量）、票据积压预警、客户风险（长期未交票/零申报异常） | Given 老板登录，When 查看驾驶舱，Then 可见每人当日处理量与全机构积压趋势图 |
| FR-06 | 客户轻门户 | H5 上传票据 + 进度查询；免登录（手机验证码）| Given 客户上传 10 张票，When 会计打开对应账套，Then 票据已在待处理池且带客户标记 |
| FR-07 | 合规留痕 | 所有审核操作记录操作人/时间/前后值，导出审计包 | Given 稽查场景，When 导出某户某月操作日志，Then 输出完整不可篡改的操作链 |
| FR-08 | 部署与备份 | Docker 一键部署脚本；每日自动备份到本地+可选 MinIO 异地 | Given 断电重启，When 恢复备份，Then 数据回到最近备份点且可验证 |
### 2.4 非功能需求
| 项 | 要求 |
|----|------|
| 并发 | 10-50 人机构同时在线，OCR 队列峰值 500 张/小时 |
| 数据安全 | 全私有化，无外网依赖（发票验真等需联网的功能做成"可选模块"并明示）；账套级 RBAC 权限 |
| 性能 | 票据池列表 <1s；驾驶舱报表 <3s |
| 可维护 | 升级不停机（K8s 滚动）；规则/科目模板热更新 |
### 2.5 版本规划
| 版本 | 内容 | 商业目标 |
|------|------|----------|
| V1（6 个月） | FR-01~04 + 08（核心生产线：票据→凭证草稿） | 3-5 家种子机构免费共创，打磨到"会计离不开" |
| V1.5 | FR-05~07（驾驶舱/客户门户/审计） | 转付费：首批 10-20 家 |
| V2 | 申报准备包（税表预填，不碰申报本身）+ 工资条模块 + T2 票据引擎 API 对外 | 渠道/OEM 收入 |
### 2.6 定价（企业级逻辑：按"产能"而非按"人头"）
| 版本 | 定价 | 逻辑 |
|------|------|------|
| 种子版 | 0 元（6 个月） | 换共创反馈+案例授权 |
| 标准版 | ¥8,800/年/机构（≤30 户），每 +50 户 +¥3,000/年 | 一户代账费 200-500 元/月，30 户年流水 7-18 万，8800 元 ≈ 增收 5-10 户的边际成本，ROI 直接可算 |
| 私有部署旗舰版 | ¥28,000 首年 + ¥9,600/年 维保 | 含 K8s 高可用部署、上门实施 |
| 按人效定价的备选口径 | 每会计席位 ¥1,800/年 | 若机构喜欢按席位买 |
> 对比锚点：头部财税 SaaS 席位价普遍数千元/人/年；本方案定低价是因为对手是"代账会计继续手工干"，不是其他软件。
### 2.7 销售路径（B 端小团队打法）
1. **共创先行**：3-5 家本地代账机构免费部署，锁定"月度人效数据"作为案例素材。
2. **渠道复用 v0.2 的 C 端漏斗**：短视频内容从"会计个人效率"升级为"代账老板的产能焦虑"（一人只能带 50 户 → 平台帮你带到 150 户），C 端工具箱成为机构版的自然引流品。
3. **代账社群 + 培训机构分销**：代账行业有密集的微信社群与培训班（继续教育学分体系），讲师分销佣金 30%。
4. **区域代理商**（V2 后）：财税软件代理商现成的机构客户名单。
### 2.8 主要风险
| 编号 | 风险 | 等级 | 应对 |
|------|------|------|------|
| RK-01 | 凭证科目映射准确率不达预期，会计觉得"改草稿比手做还慢" | 高 | 种子期重点打磨；规则模板按行业分库（商贸/服务/建筑）；始终定位"草稿+人工确认"不吹全自动 |
| RK-02 | 增值税申报环节政策敏感，做深有合规风险 | 中 | V1/V1.5 只做"申报准备"，不碰申报提交；上线前过法务 |
| RK-03 | 机构老板付费意愿低于预期（代账行业利润薄） | 中 | 定价挂钩"多接 5 户"的增收逻辑；先共创再收费 |
| RK-04 | 私有化部署的运维负担（客户环境千奇百怪） | 中 | 单机 Docker 版为主推形态；远程运维需客户授权并留痕 |
| RK-05 | 头部厂商下场做代账版（如某刻推出机构版） | 低-中 | 靠"私有化+轻量+贴身服务"错位；小团队迭代速度是优势 |

## 三、与 C 端工具箱的关系（产品矩阵）
```
财务提效软件产品矩阵
├── 个人版（v0.1/v0.2 方案）：¥299 买断 ── 引流 + 现金流 + 技术验证
├── 代账版：¥899 买断 ── 个人版的机构轻量形态，向上销售桥接
└── 企业版（本文 T3 方案）：¥8,800/年起 ── 真正的利润主力
```
**核心策略：三层产品共用同一引擎层（OCR/规则/台账/报表），C 端赚现金流与口碑，B 端赚利润。**
## 四、待你拍板的问题
1. **创业形态**：全职投入还是业余先做 C 端验证 6 个月再上 B 端？（B 端共创需要你能响应机构现场问题）
2. **首选切入**：T3 主线是否认同？还是你更想绑定 T6（监控告警，复用银河项目）走另一条路？
3. **种子机构资源**：你身边有没有可以直接谈的代账机构/代账会计？（决定共创冷启动速度，这是 V1 成败第一变量）
4. **合规底线确认**：V1 只做"凭证草稿"不做"自动申报"，是否接受？
